# Mini QLab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Build a tested React/Vite Mini QLab cue-list controller that is usable as a browser demo and as an npm React component library.

**Architecture:** Put serialisable cue configuration and runtime status helpers in `src/lib/cues.js`, and isolate asynchronous group sequencing in `src/lib/cueEngine.js`. `src/PAGEXQ.jsx` connects those tested modules to the UI, browser storage, external triggers, and `onEvent`; focused components render the toolbar, cue groups, table, and active panel.

**Tech Stack:** React 18, Vite 5, Tailwind CSS 3, cron-parser, Vitest, jsdom, React Testing Library.

**Spec:** `docs/superpowers/specs/2026-09-03-mini-qlab-design.md`

## Global Constraints

- Use React, Vite, Tailwind CSS, Vitest, and Testing Library.
- Export the default component from `src/PAGEXQ.jsx` and its CSS from `src/styles.css`.
- Store groups in `qlab_cues` and theme selection in `mini-qlab-theme`.
- Persist only editable configuration; rebuild runtime status after load and import.
- Normalize non-empty edited commands to exactly one trailing `/`.
- Do not include a transport, OSC sender, MIDI sender, LTC decoder, or HID driver.
- Cancel every pending timer when a group stops or the component unmounts.

- [x] **Step 3: Implement one engine lifecycle**

```js
async start({ group, groupIndex }) {
  this.stop(group.id, groupIndex, group.name, false);
  this.emit('sequence:started', group, groupIndex);
  for (const cue of group.cues) {
    if (!this.running.has(group.id)) return;
    this.status(group.id, cue.id, { status: 'LIVE', progress: 0 });
    await this.wait(group.id, cue.waitMs, cue.id);
    if (!this.running.has(group.id)) return;
    this.status(group.id, cue.id, { status: 'DONE', progress: 100 });
    this.emit('cue:dispatched', group, groupIndex, cue, { command: cue.command, source: 'sequence' });
  }
}
```

Use managed timeout IDs per group. Emit `cue:started`, completion, cancellation, and loop restart; progress updates must be bounded 0–100 and no stopped timeout may dispatch.
